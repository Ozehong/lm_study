# **技术拆解**

## **模型架构**

**MoE混合专家模型**

对于每一个token的路由到对应的expert中，公式如下：

$$\mathbf{h}_{t}=\sum_{i = 1}^{E} \text{Softmax}_{i}(\text{TopK}(\mathbf{x}_{t} \cdot \mathbf{W}_{g})) \cdot \text{FFN}_{i}(\mathbf{x}_{t})$$

**遇到问题**：当扩展到更大的模型时，遇到了路由崩溃

**解决办法**：在辅助loss的基础上引入Gshare的全局路由。对于全局路由进行跨EP组的全局token调度策略。

引入了一个额外的allgather通信开销，以便在跨不同EP组分发token之前同步等待每个专家处理的令牌数量。

## **Linear Attention**

* 利用“**right product kernel trick**”的性质，把原来的 $$\mathbf{O} = \text{Norm}((\mathbf{Q}\mathbf{K}^{\top})\mathbf{V})$$换成 $$\mathbf{O} = \text{Norm}(\mathbf{Q}(\mathbf{K}^{\top}\mathbf{V}))$$。

![](images/image-3.png)

* **Linear Attention 是一种类 RNNs 的方案**

  > 近一段时间，看起来更像 RNNs 的方法不断涌现，发明者们更愿意称其为 State Space Models (SSMs)，比如：Mamba、rwkv、RetNet 等等。在推理阶段，类似 RNNs，这类方法在生成单个 Token 时的复杂度为常量，与序列长度 N 无关；在训练阶段，则结合了各种细节设计来解决难以并行化的问题。 从这个角度来看，Linear Attention 或者 Lightning Attention 就属于这类方法，尽管 Linear Attention 是基于 Softmax Attention 的公式推导而来的。
  >
  > 认为类 RNNs 这个划分不对的话勿喷，Vanilla Transformer 都可以写成 RNN 的形式，可参考：[时空之章：将Attention视为平方复杂度的RNN](https://kexue.fm/archives/10017)，Transformer、 Linear Attention、 SSMs 的数学形式都可以相互转化，也可参考：[Transformer，SSM，Linear Attention的联系与理解](https://zhuanlan.zhihu.com/p/705837508)。
  >
  > 有了上面这么多铺垫，使用 Linear Attention 的出发点就很自然了：在训练阶段，对于整条序列来说，将复杂度降低为 O(N)，而 Lightning Attention 就是 Linear Attention 并行化困难的一种解决方案；在推理阶段，将生成单个 Token 的复杂度降低为常量。

  > 具体的 Linear Attention 结构有很多种，不同结构选择不同的函数 $$\phi$$和 $$\Phi$$，也可以选择 $$\phi≠\Phi$$。MiniMax-01 的作者之一在早前的工作中还论证分母 $$\sum_{j = 1}^{i} sim(Q_i, K_j)$$的 scaling 操作对 `Linear Attention` 存在负面影响，把 scaling 操作替换成了 LayerNorm 操作。MiniMax-01 也遵循了这个设计，这也是为什么其技术报告的 Linear Attention 部分的公式（上图的公式（2）&（3））把 Softmax 换成了 Norm。

  > 论文 [Transformers are RNNs: Fast Autoregressive Transformers with Linear Attention](https://link.zhihu.com/?target=http%3A//arxiv.org/abs/2006.16236) 选择了 $$\phi(x)=\varphi(x)=elu(x)+1$$。更多的可以参考：[线性Attention的探索：Attention必须有个Softmax吗？](https://link.zhihu.com/?target=https%3A//kexue.fm/archives/7546)、[Performer：用随机投影将Attention的复杂度线性化](https://link.zhihu.com/?target=https%3A//kexue.fm/archives/7921)、[The Devil in Linear Transformer](https://link.zhihu.com/?target=http%3A//arxiv.org/abs/2210.10340)。

## **MoE优化**

> MoE架构优化的主要目标是最小化通信开销，特别是对于使用全对全通信的MoE模型。为解决这一问题，研究实现了基于token分组的重叠方案。

> 在该方案中，全对全通信在EP通信组内执行，并与不同专家组的token处理重叠。为确保通信结果的正确性，每个处理组需要顺序执行通信操作。因此，不同组之间的全对全通信无法重叠，导致出现空闲时间。

![](images/image-5.png)

> 这种方法带来了显著的性能提升。然而，通过更详细的分析发现，MiniMax-Text-01模型的专家配置存在一个关键权衡：当使用TP来分割专家参数时，计算强度变得过低，影响计算效率；但如果不使用TP，则参数数量过大，需要激活更大的流水线并行(PP)配置。挑战在于PP不能减少存储激活值所需的内存占用。

> 这一限制对长上下文模型的训练特别不利，因为内存消耗的增加并未带来相应的计算效率或训练速度提升。因此，开发新的参数分割策略，在内存使用和计算强度之间实现巧妙平衡，对优化特定模型和任务的训练过程至关重要。

> 为实现更高效率，研究首先引入了一个新的处理组ETP（专家张量并行），专门用于管理专家的权重分割。同时，提出另一个独特的处理组EDP（专家数据并行），用于封装相同专家的数据并行性。系统中定义参与训练的GPU总数为 \_ ，需满足两个关键条件：
>
> $$world\_size = size_{PP} \times size_{DP} \times size_{CP} \times size_{TP}$$
>
> $$world\_size = size_{PP} \times size_{EDP} \times size_{ETP} \times size_{EP}$$

> 这种配置使MoE组件具备灵活定义专家分布、管理专家权重分割以及独立配置ZeRO（零冗余优化器）算法的能力。基于此实现，研究能够完全解耦MoE组件和非MoE组件的并行策略。在此基础上，可以灵活配置ETP以在内存使用和计算强度之间实现最优平衡。此外，为降低通信开销，研究设计了EP-ETP重叠策略，旨在最大化网络资源和计算资源的利用率。

![](images/image-6.png)

**通过上述优化策略，研究为MiniMax-Text-01模型的MoE结构中的特定专家规格实现了存储和计算强度的均衡配置。此外，基于这些优化，MoE组件的纯通信开销相比优化前降低了50%，显著提升了训练效率。**

## **长上下文优化**

> 对于lightning attention，LASP（线性注意力序列并行）算法利用CP通信组来实现长序列的扩展。如图(a)所示，LASP算法要求所有CP级别进行发送-接收操作来交换中间键值（ KV ）块结果。这一要求在CP级别之间形成了顺序依赖关系，导致计算必须以串行方式进行。这种顺序依赖性显著降低了训练过程的整体效率，因为系统的固有并行性未能得到充分利用
