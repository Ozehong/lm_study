# **Introduction**

> * **研究背景：**&#x4F20;统的**next token prediction范式的scaling law受限于可获得的高质量训练数据**，本技术报告旨在研究探索一个新的scaling的维度，**将 RL 与 LLM 结合，模型通过奖励引导学习探索，而不限于预先收集的静态数据集**
>
> * **研究内容：**
>
>   * **长文本Scaling：**&#x52;L训练的window length最长到128K，并且观察到性能随着长度增加持续提升
>
>   * **改进的策略优化：**&#x63A8;导 **Long CoT RL范式**，并使&#x7528;**&#x20;Online Mirror Descent的变体算法**，以及采样策略和长度惩罚实现鲁棒策略优化
>
>   * **简单的RL框架：**&#x968F;着context length scaling，**学习到的CoT展现出planning, reflection, correction等能力**，且**没有使用复杂的MCTS、Value Model和PRM**
>
>   * **多模态能力：**&#x6B;1.5是一个多模态大模型，在多模态推理数据上也进行了RL训练
>
>   * **long2short：**&#x901A;过多种方法实现**LongCoT模型能力迁移/蒸馏到ShortCoT模型**
>
> * **研究贡献：**
>
>   * **RL的context length scaling对大模型的持续提升至关重要**

# **Method**

方法整体流程：

![](images/diagram.png)

> ### **RL prompt set优化**
>
> 强化学习prompt set的**质量和多样性对强化学习的有效性至关重要**，**构造良好的prompt set不仅可以引导模型进行稳健的推理，还可以降低reward hacking以及过拟合一些回答pattern上**
>
> * **数据多样性覆盖：STEM, 代码, 通用推理**等领域数据都要覆盖到，提升模型泛化性
>
>   * 自动化过滤收集富含推理过程且可以直接评估的 text和image-text question-answering数据
>
> * **数据难度平衡：**&#x4ECE;**简单到难全覆盖，促进模型的课程学习以及防止过拟合特定难度的数据**
>
>   * 通过SFT模型对prompt多次采样，计算通过率，用**1-通过率**作为难度标签标记在数据中
>
> * **准确的可评估性：**&#x7528;到的prompt数据应当能够让模型生成正确的推理过程，而不是让模型去靠记住特定的pattern或者随机猜测，使得评估结果并不可靠
>
>   * 些复杂的推理问题可能有相对简单且容易猜测的答案，从而导致含有错误的验证，**模型通过不正确的推理过程得出正确的答案**
>
>   * **过滤容易出现这种问题的数据：多选题, 判断题 以及基于证明的题目**
>
>   * **过滤模型容易猜出来答案的数据：不用CoT推理步骤，采样多个大模型回答，猜对概率大于阈值就过滤掉**

> ### **Long-CoT SFT**
>
> 基于得到的RL prompt set，通过**prompt engineering，采用类似拒绝采样的方法构建高质量Long CoT warm-up数据集**，包含文本和图像推理路径数据，涵盖**planning、evaluation、reflection和exploration**等关键推理过程
>
> 对base 模型用此数据集进行SFT，得到了初步生成更详细逻辑步骤的能力

> ### **Reinforcement Learning**
>
> * **问题设定：**
>
>   $$z_t \sim \pi_{\theta}(\cdot|x,z_1,\ldots,z_{t - 1})$$表示生成中间推理步骤，$$y \sim \pi_{\theta}(\cdot|x,z_1,\ldots,z_m)$$表示生成最终答案，策略优化目标为最大化期望奖励：
>
>   $$\max_{\theta} \mathbb{E}_{(x,y^*) \sim \mathcal{D},(y,z) \sim \pi_{\theta}} [r(x,y,y^*)]$$
>
>   其中 $$y^*$$是正确答案，**奖励值是通过奖励模型给出的一个基于模型生成答案和参考正确答案的0\~1之间的值，对于不同的情况用到的奖励模型不同：**
>
>   * **可直接验证的问题：直接rule-based，比如code**
>
>   * **答案形式不固定的的问题：训练一个奖励模型，预测模型生成答案是否match正确答案**
>
>   **让大模型通过RL过程生产CoT，与传统先用一套MCTS方法生成CoT数据再知道模型学习的方法不同，模型不应仅仅follow一系列推理步骤，而是应该通过利用RL探索的想法来学习关键的planing技能，包括错误识别、回溯和解决方案改正等**
>
> * **策略优化：**&#x91C7;用了一个Online Policy Mirror Descent的变体算法，实际上不用管这个算法名字，就是**策略梯度的一个变体加上KL散度的行为约束**，公式如下，值得注意的是所用sample是reference策略采样的，所以这个算法是一个 Off-Policy方法
>
>   可以看到该算法也是相当于**将Value Model 优化掉了**，极大地提高了训练效率
>
>   **训练结论：**&#x5E94;该**鼓励模型探索不同的推理路径，以增强其解决复杂问题的能力**。主要目标并不局限于在训练问题上获得高准确率，而是专注于让模型学会有效的问题解决策略，最终提高其在测试问题上的性能

>
>   * **课程采样：**&#x7B80;而言之就是从较简单的任务开始训练，然后逐步进行更具挑战性的任务
>
>   * **优先级采样：**&#x7B80;而言之就是成功率较低的问题获得较高的抽样概率

> ### **Reinforcement Learning**
>
> * **其他细节：**
>
>   * **数学任务的奖励建模：**&#x6570;学问题通常正确答案可能有不同的形式，比如分数和小数，所以需要精确的奖励模型，本技术报告探索了传统RM和CoTRM，**传统Value-head RM输入问题、参考答案和生成答案然后输出一个标量值；CoT RM则是在CoT数据上训练得到，在给出奖励分数前，先会有生成推理步骤，最后再给出奖励**。二者都采用了800K数据训练，最后CoT RM准确率比传统RM高14%
>
>   * **视觉数据：**&#x5305;含**真实世界数据、合成视觉推理数据以及文本渲染数据**
>
>     * 真实世界数据涵盖了一系列不同年级水平的科学问题，这些问题需要图形理解和推理能力，还包括需要视觉感知和推断的位置猜测任务，以及涉及理解复杂图表的数据分析等其他类型的数据
>
>     * 合成视觉推理数据是人工生成的，包括通过程序创建的图像和场景，旨在提高特定的视觉推理技能，例如理解空间关系、几何图案和物体交互
>
>     * 文本渲染数据是通过将文本内容转换为视觉格式生成的，这使得模型在跨不同模态处理基于文本的查询时能够保持一致性。通过将文本文档、代码片段和结构化数据转换为图像，我们确保无论输入是纯文本还是渲染为图像的文本（如屏幕截图或照片），模型都能提供一致的响应。这也有助于增强模型处理文本密集型图像的能力

> ### **Long2Short**
>
> 迁移/压缩/蒸馏 LongCoT模型的能力、先验到ShortCoT模型是上
>
> * **模型融合：**&#x76F4;接融合LongCoT模型和ShortCoT模型的权重
>
> * **最短拒绝采样：**&#x6A21;型生成回答长度方差较大，采样多个回答选择最短的正确回答用于小模型的SFT
>
> * **DPO：**&#x540C;样采样多个，选择最短的正确回答为chosen，更长的为rejected
>
> * **Long2short RL：**&#x4F7F;用长度惩罚Reward，同时大幅度减少生成context最大长度，进一步Long2Short，然后再进行一个阶段的RL，采用的第一个阶段RL过程中间的模型checkpoint，兼顾性能和token efficiency

> ### **其他训练细节**
>
> **k1.5模型是先经过pretrain和SFT之后才做RL的**
>
> * **Pretrain：**&#x7ECF;过三个阶段，1）vision-language预训练，先建立坚实的语言基础，然后逐步进行多模态整合；2）冷却阶段，使用精心挑选和合成的数据巩固模型能力，尤其针对推理和基于知识的任务；3）长上下文激活阶段，将序列处理能力扩展到 131,072 个token
>
> * **SFT：**&#x666E;通的SFT，数据集包含约100万个文本示例。具体来说，500K通用问答，200K编码，200K数学和科学，5000创意写作，20K长上下文任务，如总结、文档问答、翻译和写作。此外，还有100万个文本-视觉示例，涵盖各种类别，包括图表解读、光学字符识别、基于图像的对话、视觉编码、视觉推理以及带视觉辅助的数学/科学问题

> ### **RL infra**
>
> * **LLM大规模强化学习训练系统：**&#x4D;aster负责管理各个worker之间的数据和通信流动，Trainer负责进行梯度更新，Rollout worker定期从Trainer download新的权重并应用到采样过程中，收集到的数据都存进replay buffer中，
>
> * **Partial Rollout：**&#x53EF;以有效应对处理长CoT时面临的挑战，**通过设定固定的输出token budget，限制了每个rollout的长度，未完成的部分会被保存到replay buffer中，并在下次迭代中继续**。这确保了不会有单个长轨迹独占系统资源。此外，由于rollout worker进程是异步运行的，当一些进程处理长轨迹时，其他进程可以独立处理新的、更短的rollout任务。这种异步操作通过确保所有rollout worker进程都能为训练过程做出贡献，最大化计算效率，从而优化系统的整体性能
>
>   **此外还会检测重复序列，进行提前终止**

![](images/image-10.png)

> ### **RL infra**
>
> * **训练推理的混合部署：**
>
>   * **训练阶段：**&#x4E00;开始，Megatron和 vLLM在各自独立的容器中运行，由一个名为 Checkpoint Engine的中间进程封装管理。Megatron 启动训练流程。训练完成后，Megatron 卸载 GPU 内存，并准备将当前权重传输给 vLLM&#x20;
>
>   * **推理阶段：**&#x63A8;理阶段：在Megatron完成卸载后，vLLM以虚拟模型权重启动，然后通过Mooncake用Megatron传输过来的最新权重对其进行更新。Rollout操作完成后，Checkpoint Engine会停止所有vLLM进程
>
>   * **后续训练阶段：**&#x4E00;旦释放分配给vLLM的内存，Megatron重新加载内存并启动新一轮训练&#x20;
