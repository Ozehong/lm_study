> Seed-Thinking-v1.5&#x662F;**&#x20;200B 参数的MoE模型，激活参数为20B**，benchmark 表现为 **AIME 2024 86.7，Codeforces 55.0，GPQA 77.3**，展现出在STEM领域和编程方面卓越的推理能力。非推理任务胜率比DeepSeek R1 高出8%，这表明其应用范围更广

# **Introduction**

> ### **整体介绍**
>
> o1、R1、Gemini 2.5 pro 和 Claude 3.7等模型在逻辑推理、数学、编程任务上取得的进展突显了推理模型正朝着更**结构化、高效且可扩展**的方向转变，研究重点集中在**训练效率、长思维链和大规模强化学习**
>
> 文本主要对三个关键点：**训练数据、RL算法和 RL基础设施**投入了大量精力：
>
> * **训练数据：**
>
>   * **过多非思维链的 SFT 数据会显著降低模型的探索能力**
>
>   * RL 数据：**STEM问题、代码相关任务、逻辑推理，以及创意写作和对话等非推理数据**。在这些数据中，**逻辑推理数据对 ARC-AGI benchmark 的性能提升有显著贡献**，**数学数据展现出强大的泛化能力**，能够在多个任务上带来广泛的性能提升
>
> * **RL 算法：**&#x63A8;理模型的**强化学习训练极不稳定经常会中断，尤其是对于没有经过 SFT 的模型**。Seed开发了**VAPO 和 DAPO**两种算法来稳定强化学习训练（这里可以回归**3.3.10和3.3.11章[ 3.3 RLHF 基于人类反馈的强化学习](https://kcnd4kn8i6ap.feishu.cn/wiki/TQqTwh2uwiSrqYktIPccTQOcn0g?fromScene=spaceOverview#share-CtDCdrWgRonWOhx55ifc5SCjnqb)**）
>
> * **RL infra：**&#x4E3A;了处理异构工作负载，本文采用**解耦的流式采样（decoupled streaming rollout）架构**，通过**优先样本池（prioritized sample pools）**&#x5F02;步处理轨迹生成，迭代周期**比同步框架快3倍**。该系统还支持具有**自动故障恢复**功能的混合精度训练

# **Data**

> ### **RL 训练数据**
>
> 强化学习训练数据主要由两部分组成：**有确定答案的可验证问题和没有确定答案的不可验证问题**。模型的推理能力主要来源于第一部分，并且可以泛化到第二部分
>
> #### **可验证问题**
>
> * **带答案的 STEM 问题**
>
>   * **数据来源：100K高质量的竞赛级题目**，涵盖**数学（超80%）、物理和化学**，来源于开源数据集、公开竞赛以及专有题库
>
>   * **数据清洗**
>
>     * 首先**剔除表述不完整、符号不一致或要求不明确**的题目
>
>     * 对于剩下的题目，使用 Doubao-Pro 1.5 生成多个答案。如果**模型在某道题上的 WoN（Worst of N）得分为 1，那么这道题就被认为过于简单而被剔除**
>
>     * 最后，有些题目的参考答案可能不准确。使用最先进的推理模型为每道题生成多个候选答案。如果模型的答案与参考答案不一致，但**模型的输出内部一致性很高**，或者只包含极少量的推理 tokens，就认为参考答案是错误的。然后，人类专家会对这些题目进行人工验证，以确保参考答案的正确性
>
>     * 还进行**数据增强**，使数据更适合学习和评估。具体来说，将**选择题转换为填空题或简答题形式**，以消除猜测的可能性，更好地评估推理能力。并且对**某些数学题目进行修改，尽可能确保答案为整数**
>
> * **带单元测试的 Code 问题**
>
>   * **数据来源：**&#x4F18;先选取高质量且具有挑战性的算法任务，主要来源于备受推崇的程序设计竞赛
>
>   * **数据筛选：**&#x5BF9;数据进行筛选，确保每个问题都包含：**清晰的问题描述、一组单元测试和一个检查脚本**。单元测试用于验证解决方案的功能正确性，而检查脚本则用于执行额外的约束条件，如输出格式和边界情况。此外还进行难度筛选，确保问题具有适当的复杂度，并且适用于实际的算法推理
>
>   * **数据评估：**&#x5F00;发了一套**离线评估机制**，用于高效的本地验证，所有的训练和评估问题都集成到内部的**代码沙盒环境**中，以便直接执行和评估模型生成的代码
>
> * **适合自动验证的逻辑推理数据**
>
>   * **数据来源：**&#x6536;集了22项常见的逻辑推理研究任务，如**24点游戏、迷宫、数独**等。对于每项任务，构建一个数据生成器和一个答案验证器。**数据生成器可以自动生成大量的训练和评估数据**，还可以配置生成问题的难度。训练过程中根据模型在特定任务上的表现，逐步调整训练数据的难度。**答案验证器会严格评估生成结果的正确性，并且可以作为奖励函数无缝集成到强化学习流程中**。强化学习训练使用了10K推理puzzle数据
>
> #### **不可验证问题**
>
> * **数据来源：**&#x6B64;类问题主要包括**需要基于人类偏好进行质量评估的非推理任务**，比如**创意写作、翻译、知识问答、角色扮演等任务**。这部分数据集的 prompts 来源于 Doubao-1.5 Pro的 RL训练数据
>
> * **数据筛选：**&#x5254;除样本得分方差低和难度低的数据。具体来说，使用 SFT 模型为每个 prompt 生成多个 response，然后用 Reward Model 对其进行评分。**得分方差低的 prompts 会被剔除，因为它们的采样多样性有限，改进潜力极小**。在 Doubao-1.5 Pro RL 训练过程中，**奖励得分提升超过特定阈值的 prompts也会被剔除，此类数据可能过于简单，或者在数据集中已大量存在，对此类样本过度优化会导致模型探索空间过早收敛，进而降低性能**
>
> * **数据评分：**&#x91C7;用 **pair-wise rewarding**的方法进行评分和强化学习训练。比较两个样本的相对质量，这种方法有助于模型更好地理解用户偏好，提高生成结果的质量和多样性

# **Reward Modeling**

> ### **可验证问题的奖励建模**
>
> * **Seed-Verifier：**&#x57FA;于人工设计的原则（Principles），让 LLM 直接去评估 `<question, reference, answer>`的三元组和模型生成的 answer，如果**参考答案和模型生成答案很大程度上等效/一致，LLM 返回 `YES`否则`NO`**，等效不是完全一致，而是根据计算规则和数学原理来证明两个答案收敛到同样的数学意义
>
> * **Seed-Thinking-Verifier：训练了一个 verifier 来生成评估的详细的推理细节路径**，可以评判参考答案和模型生成答案之间的相似处和区别，提供细致的判断结果。这里还可以**参考 Deepseek-GRM 的结论[ 8.1.4 Deepseek-GRM](https://kcnd4kn8i6ap.feishu.cn/wiki/R5tcwZS4oivFNfkG5QTclfeInyg)**
>
> #### **Seed-Thinking-Verifier 可以解决 Seed-Verifier 的三个主要问题**
>
> 1. **Reward Hacking：**&#x6CA1;有 thinking 过程的话，很可能**利用漏洞给予一些没有真正解决问题的回答高奖励**，加入 detailed thinking 推理之后可以有效减轻reward hacking现象
>
>    > Reward Hacking 可以复习**3.3章中的概念[ 3.3 RLHF 基于人类反馈的强化学习](https://kcnd4kn8i6ap.feishu.cn/wiki/TQqTwh2uwiSrqYktIPccTQOcn0g?fromScene=spaceOverview#share-JZardPuc7oxRxmxCdrucNq4qn1c)**
>
> 2. **预测的不确定性：**&#x4E3E;例说明，答案 $$2^{19} \text{vs}\ 524288$$知识形式不一样，Seed-Verifier 有较大概率返回 `YES`或者`NO`，但是 Seed-Thinking-Verifier 的回答就很一致性&#x20;

> ### **不可验证问题的奖励建模**
>
> 训练了一个奖励模型，训练数据来自于 Doubao-1.5 Pro 中所使用的人类偏好数据，主要包含创意写作和摘要等类别。**奖励模型采用了 pair-wise generative RM的形式**（这里也可以参考[**&#x20;8.1.4 Deepseek-GRM**](https://kcnd4kn8i6ap.feishu.cn/wiki/R5tcwZS4oivFNfkG5QTclfeInyg)），奖励模型会评估两个回答的优劣，并**将回答`YES`或`NO`的概率作为最终奖励分数**
>
> 这种方法能让模型在评分时直接比较不同回答之间的差异，从而**避免过度关注无关紧要的细节**，提高了强化学习训练的稳定性

# Approach

> ### **SFT 阶段**
>
> 对比直接从 Base Model 直接进行 RL，**SFT 模型可以提供更可读的输出、更少的幻觉**。SFT 用到了300K可验证数据 + 100K不可验证数据。
>
> #### **生成高质量 LongCoT 数据的workflow**
>
> 1. **冷启动：**&#x4E13;家 prompt 工程或者与初始模型进行交互式对话生成各种推理模式的回答，积累数十个冷启动样本就可以训练一个 LongCoT 的推理模型了
>
> 2. **拒绝采样：**&#x5229;用 Seed-Verifier 进行拒绝采样，包括数学、Code还有其他领域
>
> ### **RL 阶段**
>
> RL 的数据主要包含三类：
>
> * **可验证数据：**&#x4ECE; Verifier 获得反馈，因为可以直接用一些标准验证
>
> * **通用数据：**&#x7528; Reward Model 打分
>
> * **特殊数据：**&#x4E00;部分数据结合 Verifier 和 Reward Model 的打分
>
> 具体的 RL 算法主要来自之前开发的 **DAPO 和 VAPO 算法**，这部分可以参考**3.3.10和3.3.11章[ 3.3 RLHF 基于人类反馈的强化学习](https://kcnd4kn8i6ap.feishu.cn/wiki/TQqTwh2uwiSrqYktIPccTQOcn0g?fromScene=spaceOverview#share-CtDCdrWgRonWOhx55ifc5SCjnqb)**
>
> #### **Online Data Distribution Adaption**
>
> 不同 domain 的数据进行 merge 的时候，可能会有难度差异、reward hacking 的差异等影响，使得模型的各方面能力统一提升困难。本文引入**Online Data Distribution Adaption，将 RL 过程中固定的 prompts 分布转变为自适应分布**（相当于强化学习的环境在变化），将数据干扰的负面影响降至最低，并确保在不同能力方面实现更均衡的提升

# Infrastructures

> ### **Framework**
>
> 使用 HybridFlow 构建，训练负载运行在 Ray 集群上，Dataloader 和 RL 算法都在单个 Ray Actor中实现，Training 和 Rollout都是在 Ray Worker Group上实现
>
> ### **Streaming Rollout System**
>
> 在长思维链（Long-CoT）生成过程中，由于各种 prompt 之间回复长度差异很大，导致出现严重的长尾现象，在生成过程中造成了大量的GPU空闲时间。SRS 架构将模型 evolution 与 runtime execution解耦，通过参数$$\alpha$$动态调整 on-policy 与 off-policy 样本的比例：
>
> * $$α ∈ [0, 1]$$为用最新模型 on-policy 生成的样本所占的比例
>
> * 将剩余的未完成部分$$（1 - α）$$分配给版本化模型快照（versioned model snapshots）的 off-policy 去 rollout，通过在独立资源上对部分生成结果进行异步延续的方式无缝集成
>
> ### **Training System**
>
> * **并行机制：张量并行（TP）/专家并行（EP）/上下文并行（CP）与全分片数据并行（FSDP）相结合**来训练 Seed-Thinking-v1.5，**注意力层应用了TP/CP，在MoE层应用了EP**
>
> * **序列长度平衡：**&#x5728;数据并行（DP）的各个进程中，有效序列长度可能不均衡，导致计算工作负载不均衡和训练效率低下。利用 KARP 算法，在一个 mini batch 内重新排列输入序列，使其在mini batch之间达到平衡
>
> * **内存优化：layer-wise重计算、激活值卸载和优化器卸载**
>
> * **自动并行：**&#x5F00;发AutoTuner采用基于性能分析的解决方案对内存使用情况进行建模，估计各种配置的性能和内存使用情况，以获得最优配置
>
> * **检查点：**&#x91C7;用 ByteCheckpoint 支持以最小的开销从不同的分布式配置恢复检查点
