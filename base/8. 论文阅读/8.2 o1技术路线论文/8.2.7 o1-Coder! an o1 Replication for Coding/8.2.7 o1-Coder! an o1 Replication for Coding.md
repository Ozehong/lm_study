# o1-Coder：代码任务的o1复现技术报告

> 来自北交大的团队介绍了o1-Coder，这是一个旨在复制 OpenAI 的 o1 模型并专注于代码任务的项目。o1-Coder集成了**强化学习RL和MCTS以增强大模型的System-2思维能力**。o1-Coder的框架主要包括**训练一个测试用例生成器（TCG）用于标准化代码测试，使用MCTS生成带有推理过程的代码数据，最后迭代地微调策略模型**。目前代码部分开源，并公布后续更新计划，包括RFT训练代码
>
> **论文链接: https://arxiv.org/pdf/2412.00154**
>
> **代码链接：<https://github.com/ADaM-BJTU/O1-CODER>**

# 一、研究背景

> * **o1 模型的影响：**&#x4F;penAI 的 o1 模型具有出色的**System-2思维能力（更深入、审慎和逻辑的思考步骤）**，推动了 AI 推理模型研究的发展，引发众多学术和工业界的复制尝试，截至o1-coder工作出来的时间已经有的相关工作如下图所示
>
> * **现有模型局限与解决途径：**&#x4EE5;往LLMs多为**System-1能力（快速、本能但不太准确的思维模式）**，缺乏推理步骤。传统方法如思维链（CoT）提示和监督微调（SFT）存在不足，本文选择强化学习来探索生成和优化推理数据，尤其针对编码任务

# 二、研究方法

> **Framework Overview**
>
> 本文方法集成了**RL和MCTS以实现self-paly(自博弈)**，使模型能够不断生成推理数据并增强其System-2功能，但是将**self-play应用于code generation需要解决两个主要挑战：1）如何评估结果，2）如何定义推理步骤动作(思考或者搜索的行为)**
>
> * 一般来说评估代码生成结果不像评估**数学（有明确答案）或者游戏比赛（围棋等有明确规则）**&#x90A3;样方便，需要在**相应的测试环境运行生成代码检测是否通过一定数量的样例，**&#x672C;文的观点是不能假定任何时候数据集都附带测试样例，所以需要**训练一个测试样例生成器TCG(Test Case Generator)**
>
> * 关于推理步骤动作的设计有两种范式可以参考，**第一种是Think before Acting，模型先组织一个完整的CoT，然后再生成最后的答案；第二种是Think while Acting，模型推理的时候同时生成部分答案**，本文选择的是第一种思路
>
> 整体的方法框架如下图所示，包括**迭代式的生成reasoning数据、训练PRM和策略更新**

> **Test Case Generator**
>
> * **DPO阶段：**&#x4E3B;要目标是指导模型生成符合特定偏好的测试用例，从而提高测试用例生成器的性能和可靠性。训练数据使用提前构建好的偏好数据集，构建规则为：**chosen是直接sample三个完全match的测试用例，rejected则是将三个测试用例中对应的输入和输出（测试用例一般包含相应的输入和输出）打乱，得到不完全匹配的测试用例**

> **Resoning-enhanced Code Data Synthesis**
>
> * **基于伪代码的推理过程：**&#x4F2A;代码可以充当自然语言描述和实际代码之间的中间表示，**并提供一种更抽象、更简洁的方式来表达算法或程序的逻辑流程**。所以本文基于伪代码设计了三个推理步骤动作：
>
>   * **Action1 用伪代码定义算法结构**
>
>   * **Action2 修改伪代码**
>
>   * **Action3 从伪代码生成code**
>
>   这些动作确保模型在推理过程中使用伪代码作为认知工具，增强其对复杂代码生成任务的推理能力。**模型可能需要在整个推理过程中重复选择Action2**，以迭代地修改细化伪代码，直到可以用于最后的代码生成步骤，具体的动作选择prompt模板如下图所示：

> **Resoning-enhanced Code Data Synthesis**
>
> * **推理过程数据合成：**&#x4E3B;要使用**MCTS算法生成带中间奖励（价值）的推理过程数据**
>
>   $$D_{\text{process}}=\{(Q_{i},\cdots, S_{i}^{j}, v_{i}^{j},\cdots, C_{i}')\}$$
>
>   其中$$v_{i}^{j}$$表示对直到步骤$$S_{i}^{j}$$的推理路径的评估结果，$$C_{i}'$$是从最终步骤$$S_{i}^{m}$$导出的可执行代码。本文采用标准MCTS rollout算法，对于一个问题$$Q_i$$，当最终步骤达到的时候，一个完整的推理路径被表示为 $$(Q_i, S_i^1,\cdots,S_i^m)$$，**终止状态$$S_i^m$$的价值$$v_i^m$$的计算主要依据下面两个标准：**
>
>   * **编译成功率：**&#x5982;果能够成功编译为1，不能则为0
>
>   * **测试样例通过率：**&#x6309;照通过测试样例的个数计算比例分数
>
>   最后的得到 $$v_i^m=\alpha\cdot compile + (1-\alpha)\cdot pass$$，一旦得到final state的value，就进行反向传播计算路径上各个节点的$$v_i^j$$，并将他们归一化的0\~1范围内
>
> * **Policy model初始化：**&#x5728;构建推理过程数据的时候，**可以得到一批$$v_i^m=1$$，即最终结果通过编译和所有测试样例的数据**
>
>   $$\mathcal{D}_{\text{process}}^{+}=\left\{\left(Q_{i}, S_{i}^{j}, C_{i}'\right) \vert\left(Q_{i}, S_{i}^{j}, v_{i}^{j}, C_{i}'\right) \in \mathcal{D}_{\text{process}}, \mathbb{I}\left(C_{i}'\right)=1\right\}$$
>
>   使用这一批数据直接对base模型进行SFT训练得到初始化的Policy model用于后续迭代更新

> **PRM(Process Reward Model) training**
>
> PRM可以使用两种方法进行训练：
>
> * **Point-wise：**&#x6536;集的数据被组织为$$D = \{(Q_{i}, S_{i}^{1: j - 1}, S_{i}^{j}, v_{i}^{j}) | i = 1, 2, \ldots, N\}$$，其中$$N$$是样本数量，PRM使用以下目标进行训练：
>
>   $$\mathcal{L}_{PRM}^{point-wise}=-\mathbb{E}_{(Q_{i}, S_{i}^{1: j - 1}, S_{i}^{j}, v_{i}^{j}) \sim D}\left[v_{i}^{j} \log r\left(Q_{i}, S_{i}^{1: j}\right) + \left(1 - v_{i}^{j}\right) \log \left(1 - r\left(Q_{i}, S_{i}^{1: j}\right)\right)\right] $$
>
>   其中$$r(Q_{i}, S_{i}^{1: j})$$是由PRM分配的归一化预测分数
>
> * **Pair-wise：**&#x5BF9;于MCTS搜索树深度为$$d$$的节点$$n^{d}$$，其子节点表示为$$\sum_{k} n_{k}^{d + 1}$$，偏好对数据被组织为 $$D_{pair} = \{(Q_{i}, S_{i}^{1: j - 1}, S_{i}^{j,win}, S_{i}^{j,lose}) | i = 1, 2, \ldots, N\}$$。这里， $$S_{i}^{j,win},S_{i}^{j,lose}$$表示在树搜索过程中获得较高和较低值估计的推理步骤，PRM使用以下目标进行训练：
>
>   $$\mathcal{L}_{PRM}^{pair-wise} = -\mathbb{E}_{(Q_{i}, S_{i}^{1: j - 1}, S_{i}^{j, win}, S_{i}^{j, lose}) \sim D_{pair}}[\log(\sigma(r(Q_{i}, S_{i}^{1: j - 1}, S_{i}^{j, win}) - r(Q_{i}, S_{i}^{1: j - 1}, S_{i}^{j, lose})))] $$
>
>   这里的分数$$r$$未进行归一化

> **RL-based Policy Model Improvement**
>
> 本文对代码生成任务建模MDP，形式上表示为$$\mathcal{M=(V, S, A, T, R, \phi)}$$，其中$$\mathcal{V}$$表示词汇表， $$w \in \mathcal{V}$$表示模型生成的单个token，动作空间$$\mathcal{A} \subseteq \mathcal{V}^{N}$$和状态空间$$\mathcal{S} \subseteq \mathcal{V}^{N}$$是token序列的集合，**所以动作和状态都是token序列**，$$s_0$$是问题，动作$$a_i$$是一个推理步骤（包含动作类型和对应的CoT），**状态转移函数 $$\mathcal{T:S×A\to S}$$具体操作就是将当前动作$$a_t$$concat到当前状态$$s_t$$后面变为下一状态$$s_{t+1}$$**，奖励函数 $$\mathcal{R: S ×A \to \mathbb{R}^{+}}$$评估中间步骤的质量，**$$\phi$$集合PRM和ORM以产生最终的奖励信号**
>
> $$\phi\left(R_{i}, r_{i}^{1:m}\right)=\alpha(t) \cdot R_{i}+(1-\alpha(t)) \cdot \frac{1}{m} \sum_{j = 1}^{m} \gamma^{j} r_{i}^{j}$$
>
> 其中$$R_i$$是结果奖励，根据生成代码的测试通过率决定，$$\alpha(t)$$是用来平衡结果奖励和过程奖励的与推理步数相关的系数，可能**会随时间推移而减小，随着模型优化其解决方案，逐渐对中间奖励赋予更大的权重，同时随着模型接近最优策略，减少对最终奖励的强调。**&#x540E;续可以利用利用PPO或者迭代式DPO进行Policy improvement
>
> 本文为代码生成任务定义了一个专门的强化学习环境。模型的动作由基于过程的奖励和基于结果的奖励共同驱动，前者鼓励中间推理步骤，后者反映最终代码的正确性。这种双重奖励结构有助于模型随着时间推移提高其代码生成能力
>
> **可以将新的模型应用MCTS方法得到新的推理数据并加入数据集，进一步更新PRM，形成self-play训练循环，持续提升推理能力**

# 三、实验结果

> **本文只提供了一个实验结果**
>
> 采用基于MCTS的采样策略，比较了常规CoT和加入伪代码推理的CoT在MBPP基准上的的Pass@1，以及正确推理路径的最后一步的平均采样通过率（ASPR）
>
> ASPR大幅提升的实验结果表明**伪代码增强了整体推理过程**，特别是在**修改通往正确的最终输出的路径方面**
>
> > 但是Pass@1指标掉了很多，感觉效果也不是很好。。。

# 四、研究讨论

> * **经验教训**
>
>   * **数据的关键作用：**&#x41;I 发展聚焦于计算-智能转换效率，数据获取成为关键，可收集缺失数据或探索新数据类型
>
>   * **超越人类数据的意义：**&#x6F;1 模型表明可通过 RL 探索数据背后思维过程，突破人类语言数据限制，提升模型能力
>
> * **机遇与挑战**
>
>   * **机遇：**&#x81EA;博弈 RL 框架有助于将 System-2 思维应用于多领域任务，提升模型安全性，可探索 System-2 对齐
>
>   * **挑战：**&#x6F;1 类模型在实际应用中面临奖励函数泛化和环境状态更新挑战，需**构建世界模型预测状态转移，但建模难度大**，不过相关领域进展带来希望
