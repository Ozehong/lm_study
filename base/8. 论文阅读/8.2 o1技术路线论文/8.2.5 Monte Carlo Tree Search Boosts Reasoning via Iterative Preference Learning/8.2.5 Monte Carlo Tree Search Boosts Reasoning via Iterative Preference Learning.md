# MCTS-IPL：蒙特卡洛树搜索增强的迭代偏好学习

> 来自新加坡国立大学和DeepMind的研究人员提出了一种利用**MCTS蒙特卡洛树搜索生成偏好数据的迭代式DPO直接偏好优化方法来增强大型语言模型推理能力**。受AlphaZero的启发，本文利用**MCTS将instance-level奖励分解为更细化的step-level signals来收集偏好数据**，然后直接用**iterative DPO更新LLM的策略**。本文方法在 GSM8K、MATH 和 ARC-C 数据集上的表现优于 Mistral-7B 监督微调（SFT）基线，准确率分别大幅提升至 81.8%（提高了 5.9%）、34.7%（提高了 5.8%）和 76.4%（提高了 15.8%）
>
> **论文链接: https://arxiv.org/pdf/2405.00451**

# 一、研究背景

> **研究背景：**
>
> * **LLM推理能力的局限性：**&#x6A21;型能够生成看似合理的文本回答，但在面对如算术推理、常识推理等特定类型的需要严谨逻辑推导的任务时，其表现往往还有改进空间，无法始终准确、有效地完成相应推理任务，限制了它们在一些对推理要求较高场景下的应用
>
> * **LLM与偏好数据：**&#x504F;好数据的利用方式主要有**构建奖励模型和直接应用偏好更新模型策略**两种
>
> * **现有提升推理能力方法的不足：**&#x5F53;前存在多种尝试提升LLMs推理能力的方法，比如基于instance-level的学习策略、利用强化学习进行调优等。然而，这些方法可能存在诸如**无法细致地拆解奖励信号、难以保证中间推理步骤的质量、对数据的利用不够高效**或者缺乏足够的理论依据支撑等问题
>
> * **迭代方法的重要性：**&#x4E0E;传统的基于人类反馈的强化学习（RLHF）范式不同，**迭代方法强调动态和持续的改进，通过不断收集和分析数据来更新策略**，使模型更适应人类决策和推理的复杂性。AlphaZero 在各领域的成功展示了迭代方法的潜力，其结合了神经网络、强化学习技术和MCTS
>
> * **MCTS在LLM中的应用挑战：**&#x5C06; MCTS 应用于收集偏好数据以改进当前策略存在挑战，主要包括确定 **MCTS 的应用粒度（传统instance-level偏好数据收集可能丢失信息）以及 MCTS 对评估反馈的依赖（需有意义的反馈来指导策略改进）**
>
> * **MCTS蒙特卡洛树搜索：**&#x8499;特卡洛搜索（MCTS）借助树结构来进行搜索。树结构顶端的节点为根节点，没有子节点的节点称为叶子节点，节点会记录访问次数和奖励值，MCTS会综合考虑节点的访问次数和平均奖励来选择节点进行决策。MCTS分为四个步骤：**选择（Select），扩展（Expand），模拟（Simulate），回溯（Backup）**

# 二、研究方法

> **MCTS-Iterative Preference Learning：**
>
> 主要分为两步，**MCTS用于step-level偏好数据收集和迭代式DPO策略更新**。本文**使用MCTS估计的状态动作价值$$Q(s,a)$$来分配偏好，其中较高和较低的$$Q$$值的step将分别标记为postive和negetive**，构成用于后续的DPO训练的偏好对数据，然后不断迭代重复来实现策略更新

![](images/image-1.png)

**MCTS-IPL方法流程图**

> **MCTS for Step-Level Preference MCTS收集步骤级偏好数据：**
>
> * **推理过程分解与状态表示：**&#x5C06;推理过程分解为离散的step，每个step是一个token序列，定义状态$$s_t$$为推理链的前缀，通过添加新的推理步骤$$a$$将状态$$s_t$$转换为$$s_{t+1}$$ ，在LLM中$$s_{t+1}$$相当于是$$s_t$$和$$a$$的concat。利用当前模型策略$$\pi_{\theta}$$，从其概率分布 $$\pi_θ(a∣x,s_t) $$中采样候选steps，其中$$x$$是task input prompt
>
> * **Select选择阶段：**&#x9009;择阶段的目标是识别**平衡搜索质量和计算效率**的节点，使用**PUCT（Predictor + Upper Confidence bounds applied to Trees）**&#x516C;式进行节点选择：&#x20;
>
>   $${s_{t+1}}^∗=\argmax_{s_t}[Q(s_t,a)+c_{puct}⋅p(a|s_t)\frac{\sqrt{N(s_t)}}{1+N(s_{t+1})}] $$
>
>   其&#x4E2D;**$$Q(s_t, a)$$是在状态$$s_t$$采取动作$$a$$的状态动作价值，$$N (s_t)$$是状态$$s_t$$的访问次数， $$p(a∣s_t)=π_θ(a∣x,s_t)/|a|^λ$$是策略$$\pi_{\theta}$$生成步骤$$a$$的概率分布**，**增加了长度惩罚以防止推理链过长**
>
> * **Expand扩展阶段：**&#x6269;展阶段在选择过程中的叶节点发生，**生成新节点并评估奖励**。step$$a$$的奖励值 $$r(s_t,a)$$用状态奖励 $$R(s_{t+1})-R(s_t)$$差值表示，突出状态$$s_t$$处$$a$$的优势，具体状态奖励计算如下：
>
>   $$R\left(s_{t}\right)=\mathcal{O}\left(s_{t}\right)+\mathcal{C}\left(s_{t}\right)\\
>   \mathcal{C}\left(s_{t}\right)=\pi_{\theta}\left(A | prompt _{eval }, x, s_{t}\right)$$
>
>   奖励计算结合了结果正确性和自我评估，其中 $$\mathcal{O}_{s_t}$$是结果正确性分数（1表示正确terminal状态，-1表示错误terminal状态，0表示未完成的中间状态），**$$\mathcal{C}(s_{t})$$是self-evaluation结果，这里定义为在eval prompt + task input prompt + 状态$$s_t$$的条件下输出correctness相关token的概率**
>
>   上面的self-evaluation部分可能不好理解，结合本文提供的代码进一步看一下这部分是怎么计算的：
>
>   其实就是拿到**输出的token序列，找到这里面有没有出现类似选项A，B，或者表示判断的词汇correct、incorrect、wrong等，然后找到第一个这种token，提取该token对应的scores，然后对correct\_token\_ids中包含的表示正确性的token进行概率加和作为confidence分数（置信分数）**&#x5373;自我评估的值。总结来说，**这里算的是模型在当前状态输出推理步骤的时候对于自己做出的选择的自信程度（不管是输出“选项A正确”还是“选项B错误”的形式）**

> **MCTS for Step-Level Preference MCTS收集步骤级偏好数据：**
>
> * **Backup反向传播更新：**&#x4E00;旦达到terminal状态，从终止节点回溯到根节点进行自底向上的更新
>
>   $$Q\left(s_{t}, a\right) \leftarrow r\left(s_{t}, a\right)+\gamma V\left(s_{t+1}\right)\\
>   V\left(s_{t}\right) \leftarrow \sum_{a} N\left(s_{t+1}\right) Q\left(s_{t}, a\right) / \sum_{a} N\left(s_{t+1}\right)\\
>   N\left(s_{t}\right) \leftarrow N\left(s_{t}\right)+1$$
>
>   采用的更新方式是类似强化学习的定义，**状态动作价值$$Q$$通过下一时刻状态的状态价值$$V$$和即时奖励$$r$$来更新，状态价值$$V$$则定义为各个推理步骤动作状态价值的期望值（均值）**，访问次数+1
>
>   对于response生成中的每个step，本文进行K次迭代来构建MCTS搜索树。**为了平衡树构建的多样性、质量和效率，搜索宽度初始化为b1，后续步骤退火为较小的b2\<b1**。**对于深度为$$T$$的结果搜索树，获取$$T$$对step-level偏好数据**，先在当前深度通过计算各个节点的访问计数与其子节点访问计数的范围相乘的值（代表了生成的质量和多样性），选取值最大的父节点，然后选取该节点下面推理步&#x9AA4;**$$Q$$值最高和最低的两个steps作为偏好数据的正负样本**

> **Iterative Preference Learning 迭代式偏好学习：**
>
> 利用前面通过MCTS收集的step-level的偏好数据直接使用DPO来更新策略。**考虑到偏好标签中的噪声，采用保守版本的DPO，并使用MCTS中的访问计数进行自适应标签平滑**：
>
> $$\ell_{i}(\theta) = - \mathbb{E}_{x,y_{w},y_{l} \sim \mathcal{D}_{i}}[(1 - \alpha_{x,y_{w},y_{l}}) \log \sigma(\beta h^{y_{w},y_{l}}_{\pi_{\theta}}) + \alpha_{x,y_{w},y_{l}} \log (-\sigma(\beta h^{y_{w},y_{l}}_{\pi_{\theta}}))]$$
>
> 第$$i$$次迭代，其中 $$y_w,y_l$$分别表示step-level的偏好数据的chosen和rejected，超参数 $$\beta$$缩放KL约束， $$\alpha_{x,y_{w},y_{l}}$$是标签平滑变量，使用搜索树中偏好数据对应状态的访问计数计算：&#x20;
>
> $$\alpha_{x,y_{w},y_{l}} = \frac{1}{N(x,y_{w})/N(x,y_{l}) + 1}$$
>
> $$h_{y_{w}, y_{l}} = \log \frac{\pi_{\theta}(y_w|x)}{\pi_{\text{ref}}(y_w|x)}-\log \frac{\pi_{\theta}(y_l|x)}{\pi_{\text{ref}}(y_l|x)}$$为DPO loss的KL约束部分。优化后，得到更新后的策略，并重复步骤级别偏好数据收集过程，迭代更新LLM策略
>
> **使用保守的DPO以及平滑标签的作用：**
>
> * **应对偏好标签噪声：**&#x4FDD;守的DPO版本能够在优化过程中更加谨慎，防止模型过度拟合有噪声的偏好数据，从而使策略更新更加可靠
>
> * **减少过拟合提升泛化能力：**&#x6807;签平滑通过考虑 MCTS 中的访问计数来对每个偏好对应用自适应平滑，有助于减少模型对极端标签（例如，完全偏好或完全不偏好）的过度依赖，防止过拟合，提高泛化

# 三、实验结果

> **实验设置：**
>
> * **数据集：**&#x4E13;注于算术和常识推理任务，算术推理使用 GSM8K和MATH数据集，常识推理使用 ARC、AI2Science、OpenBookQA 和 CommonSenseQA 等多个数据集
>
> * **基线方法：**&#x4E0E;STaR、Crystal、Direct Tuning、LMSI、Math-Shepherd 等方法对比，同时对比instance-level迭代偏好学习和offline MCTS等变体，实验使用 Mistral-7B 作为基础预训练模型
>
> * **实验结果**
>
>   * **算术推理：**&#x5728;GSM8K和MATH 数据集上，该方法相比基线方法有显著性能提升，如在GSM8K上准确率从75.9%提升到81.8%，在MATH上从28.9%提升到34.7%。与同样使用过程监督的Math-Shepherd相比，性能相似但**无需训练单独的奖励或价值网络**，且在 MCTS 过程中结合真实解（ground-truth）可进一步提升性能
>
>   * **常识推理：**&#x5728;常识推理任务中也有性能提升，如在 ARC-Challenge（ARC-C）、AI2Sci-Middle（AI2Sci-M）和SciQ数据集上，分别比SFT方法有2.5%、3.0%和2.1% 的绝对准确率提升，**但在OBQA和CSQA 任务中，相比SFT效率较低，可能是由于基础模型缺乏特定知识，中间推理链引入的不确定性导致错误预测**

# 四、研究结论

> **结论与展望：**&#x672C;文提出的 MCTS 增强迭代偏好学习方法，利用 MCTS 作为策略改进算子，通过step-level偏好学习增强 LLM 对齐，理论分析表明在线采样对改进 LLM 策略至关重要。未来研究可从数据和算法改进方面探索，如搜索策略、历史数据和策略利用、离线与在线学习权衡等，以解决在线学习框架中的性能波动问题
